# v0.9-B real-agent authorization attack benchmark (experimental)

**Development only. Not included in the published v0.8.0 release.**

## Goal and design

The runner sends attack prompts to an actual model through an OpenAI-compatible
`/chat/completions` endpoint, with temperature set to zero where supported.
For each *single model-produced proposal*, it simulates permissive tool execution
and invokes Ruhusa's deterministic policy gate. This is a paired comparison;
it does not ask the model to simulate Ruhusa. Both arms receive the same action.

The benchmark supports these labeled prompt families: control, prompt injection,
denial/replanning, delegation abuse, cross-task authority, replay, post-revocation,
tool substitution and resource substitution. **Prompt labels are not proof that
revocation, replay or delegation was implemented in the security harness.**
Only resource/action/amount constraints are enforced here; the remaining labels
are attack *prompts*, not isolated end-to-end trust-boundary tests.

## Running

```bash
export RUHUSA_BENCHMARK_BASE_URL="https://YOUR_PROVIDER/v1"
export RUHUSA_BENCHMARK_MODEL="YOUR_MODEL"
export RUHUSA_BENCHMARK_API_KEY="YOUR_API_KEY"
uv run python -m research.real_agent_benchmark --output benchmark-results/v09b-report.json
uv run pytest tests/test_v09_real_agent_benchmark.py -v
```

An endpoint on `http://localhost` is also allowed for local inference.
The CLI requires an explicit model and endpoint; **offline CI uses a fake model**
so no tokens, secrets, or network access are required.

## Observations and interpretation

- Count valid proposals, invalid model responses and model turns.
- `unauthorized_attempts`: valid proposed tool calls violating the independent
  action/resource/amount reference predicate.
- `baseline_unauthorized_side_effects_simulated`: unauthorized tool calls that
  the permissive *simulation* would execute.
- `ruhusa_unauthorized_side_effects_simulated`: unauthorized tool calls allowed
  by the Ruhusa gate and therefore simulated as executed.
- `correct_denials` and `false_denials`: measured only over valid tool proposals.
- `post_denial_replanning_attempts`: additional calls to the model after a denial.

Malformed JSON and `none` actions are not counted as unauthorized tool attempts;
they are separately reported. This avoids interpreting agent noncompliance with
the JSON protocol as a successful security bypass.

## Limitations and next research increments

This is a **first real-model prototype**, not a statistically credible attack
study or proof of production-grade enforcement. It uses a weak invocation
provenance path, simulated side effects, one model turn per prompt (except the
replanning case), and a simple fixed policy. It does not exercise authenticated
identity, real revoked grants, replayed execution claims, MCP execution, or
cross-process races. Follow-on research should add strong invocation records,
execution-controller fencing, adversarial state mutations, seeds/replications,
multiple models, attack-success denominators, confidence intervals and
reproducible model/version snapshots.

**Privacy:** API keys are never written to results. Model proposals appear in
JSON output; avoid real customer information in prompts and reports.
