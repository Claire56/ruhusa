# Ruhusa 0.9.0rc1 — Candidate release notes

> **Pre-release candidate; not a published stable release.** The stable version remains `0.8.0` until v0.9 is independently approved and published.

## Changes since 0.8.0

- Durable, operation-bound human approvals using PostgreSQL schema v3.
- Model-driven and stateful authorization attack benchmarks with controlled, simulated side effects.
- MCP tool authorization guard and SDK router, with optional real SDK protocol round-trip test.
- Signed authenticated recovery evidence and PostgreSQL reconciliation with receipt uniqueness and atomic state transitions.
- Schema v4 (`v3 → v4`) migration for durable recovery receipt storage.
- Default-deny direct legacy `reconcile_unknown()` access, unless an explicitly unsafe compatibility option is enabled.
- D3c PostgreSQL tests for process restart, concurrent recovery, failed transactions, and abrupt termination before commit.

## Breaking changes and migration

**Direct legacy reconciliation is denied by default.** Replace callers of `reconcile_unknown()` with a trusted `PostgresAuthenticatedRecoveryService` integration. Avoid `allow_unsafe_legacy_reconciliation=True` in production. Host applications must authenticate the reconciler and restrict database roles.

**Schema upgrade:** published `0.8.0` uses schema v2; the candidate uses schema v4 via `v2 → v3 → v4`. Back up the database first; test the upgrade against a copy; schema downgrade is not supported. See [migrations](../production/migrations.md).

## Installing the candidate (after artifact validation)

```bash
pip install 'ruhusa[postgres]==0.9.0rc1'
```

This command is for **after** candidate publication to an approved package index. Until then, test the wheel built from the release branch instead. Stable users should retain `ruhusa==0.8.0`.

## Security boundaries

Authorization decisions are deterministic, but do not replace trusted authentication of people, agents, transports, reconciler evidence issuers or tool implementation registrations. Database privilege separation and signing-key rotation remain host responsibilities. Neither MCP guards nor recovery receipts make external side effects atomic or exactly once. Benchmark outcomes are not general safety guarantees.
