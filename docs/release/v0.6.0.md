# Ruhusa v0.6.0 — Execution Lifecycle, Live Authority, and Recovery

## Summary

Ruhusa v0.6.0 extends the authorization research boundary into execution.

The milestone studies three linked questions:

```text
v0.6-A
Can one valid authorization become multiple execution attempts?

v0.6-B
Can authority become invalid between execution claim and side effect?

v0.6-C
Can stale or uncertain execution be recovered without blindly retrying?
```

## Major additions

- process-local atomic execution claims;
- execution permits bound to claim ID and attempt;
- terminal `COMPLETED` replay protection;
- fail-closed `UNKNOWN` outcomes;
- safe pre-side-effect release;
- execution-time authorization revalidation;
- terminal `CANCELLED` state after live-authority failure;
- stale-claim quarantine;
- explicit UNKNOWN reconciliation;
- single-winner process-local recovery;
- stale-permit protection across recovered attempts.

## Experimental evidence

The v0.6 line extends the attack benchmark through **44 experiments**.

Key findings:

```text
operation binding
!=
execution uniqueness

authorization-time validity
!=
execution-time validity

execution-time revalidation
!=
atomic authorization + external side effect

execution-attempt uniqueness
!=
side-effect uniqueness

self-asserted recovery outcome
!=
trusted execution evidence
```

## Explicit boundaries

v0.6.0 does not claim:

- distributed consensus or execution atomicity;
- durable execution state;
- exactly-once external side effects;
- downstream idempotency;
- atomic authorization/revocation plus remote side effect;
- authenticated provenance of reconciliation outcomes;
- correctness of a compromised trusted reconciler;
- automatic recovery when the external result remains unknowable.
