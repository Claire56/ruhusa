# Ruhusa v0.7-A — Stable Public Interfaces

**Track:** Framework  
**Released baseline:** v0.6.0  
**Package version during v0.7 development:** 0.6.0

## Goal

Make the extension boundary stable before implementing persistent
infrastructure.

> Can an external developer replace Ruhusa's in-memory dependencies without
> coupling application code to research implementation classes, while
> preserving fail-closed behavior?

## Scope

v0.7-A introduces:

- Protocols for every dependency injected into `Ruhusa`;
- an `ExecutionStore` Protocol for `ExecutionController`;
- a stable framework exception hierarchy;
- explicit fail-closed backend semantics including AUD-01;
- tests proving dependency outages cannot become ALLOW;
- an intentional top-level SDK export list;
- documentation of the public extension contracts.

It does not add PostgreSQL, Redis, LangGraph, MCP, FastAPI middleware, or new
research/security invariants.

## Architecture

```text
Ruhusa
 |
 +-- PolicyStore
 +-- AuditLog
 +-- GrantStore
 +-- RevocationStore
 +-- InvocationStore
 +-- ToolRegistry

ExecutionController
 |
 +-- ExecutionStore
```

The existing in-memory implementations satisfy these Protocols through
structural typing.

## RevocationStore naming

The stable Protocol uses `snapshot()`. The v0.6 `all()` method is retained
on the bundled implementation as a deprecated compatibility alias.

## Public helper decision

`compute_arguments_digest` remains a supported SDK primitive because trusted
orchestrators need it to construct canonical `InvocationRecord` provenance.

## v0.7-B

The next production slice should implement PostgreSQL-backed stores and verify
their transactional behavior under concurrency and backend failures.

Redis is not a default v0.7-B requirement.
